**پل یک فیلترشکن برای روترهای OpenWrt است.** با نصب آن روی روتر، گوشی، رایانه، تلویزیون و دیگر دستگاه‌های متصل به شبکه می‌توانند از اتصال فیلترشکن روتر استفاده کنند؛ لازم نیست روی هر دستگاه برنامه جداگانه نصب کنید. مدیریت پل از پنل تحت وب روتر، در بخش **Services → Pol** انجام می‌شود. این پنل که LuCI نام دارد، فارسی و انگلیسی است.

**یک فایل نصب برای هر معماری:** برنامه، رابط LuCI، فونت و هسته Xray همگی داخل بسته `pol` هستند؛ نصب بسته جداگانه برای رابط یا هسته لازم نیست.

## پل برای چه کسی مناسب است؟

اگر روتر شما OpenWrt دارد و می‌خواهید فیلترشکن را برای دستگاه‌های خانه یا محل کار از یک جا مدیریت کنید، پل برای همین کار ساخته شده است. پیش از دانلود، معماری پردازنده و فضای آزاد روتر را با راهنمای نصب زیر بررسی کنید. فایل APK این پروژه مخصوص OpenWrt است و روی گوشی اندروید نصب نمی‌شود.

پل چند راه اتصال در اختیار شما می‌گذارد. انتخاب روش به اینترنت و امکانات شما بستگی دارد:

| روش | برای شروع چه لازم است؟ |
|---|---|
| Worker / VLESS | حساب Cloudflare برای ساخت Worker از داخل پل، یا دامنه و UUID یک Worker سازگار |
| WARP | ساخت حساب از داخل پل و یک آدرس اتصال مناسب |
| MASQUE | ساخت حساب مستقل از داخل پل؛ انتخاب انتقال h2 یا h3 |
| Tor یا سایفون | انتخاب روش و فراهم‌بودن دسترسی شبکه؛ برای Tor ممکن است به پل ارتباطی نیاز داشته باشید |
| کانفیگ آماده | لینک یا JSON سازگار برای واردکردن در تنظیمات |
| بدون سرور | بدون حساب؛ روش‌های فرگمنت و نویز برای برخی محدودیت‌ها، با حفظ IP عمومی شما |

برای روش‌های Cloudflare نیازی به خرید VPS نیست. موفقیت هر روش به اپراتور، محدودیت‌های شبکه و تنظیمات بستگی دارد؛ اگر یک روش وصل نشد، روش دیگری یا آدرس‌های حاصل از اسکن را امتحان کنید.

## ✨ ویژگی‌ها

- 🌐 عبور ترافیک IPv4 و IPv6 دستگاه‌های LAN، با پروکسی محلی مخصوص خود روتر.
- ☁️ ساخت Worker اختصاصی با حساب Cloudflare خودتان و ثبت حساب‌های WARP و MASQUE.
- 🔗 Worker/VLESS، WARP، MASQUE، حالت‌های بدون سرور و مدیریت بومی Tor و سایفون، مستقل یا به‌عنوان خروجی نهایی.
- 🛠️ تنظیم SNI، فینگر پرینت TLS، ECH، TCP Fast Open، فرگمنت TCP و نویز UDP.
- 🔎 اسکن IP و endpoint با درخواست HTTPS از داخل هسته واقعی؛ انتخاب نتیجه با یک دکمه.
- 🧭 دامنه‌های مستقیم و مسدود، DNS سفارشی و پروکسی زنجیره‌ای.
- 📥 ورود لینک یا JSON هسته Xray، خروجی تنظیمات و گزارش زنده قابل دریافت.
- 📊 چهار کارت وضعیت: مصرف روزانه، ۷ و ۳۰ روز اخیر به گیگابایت؛ وضعیت اینترنت؛ نسخه و اجرای هسته؛ سرور، پینگ، IP خروجی و پرچم کشور.
- 🇮🇷 تفکیک ایران با GeoIP و GeoSite پیش از ورود به هسته، با دریافت و به‌روزرسانی مستقل فایل‌ها.
- ❔ راهنمای هر بخش کنار همان گزینه با علامت سوال؛ کلید اصلی کشویی زیر کارت‌های وضعیت.
- ⏱️ نمایش مدت فعالیت روتر در بنر، زیر انتخاب زبان، با تازه‌سازی هر ۵ ثانیه.
- 🎨 رابط فارسی و انگلیسی، فونت محلی وزیرمتن در تمام بخش‌ها، تم روشن، تاریک و همراه تم دستگاه، چیدمان موبایل.
- ⚡ اعمال فوری تنظیمات با تلاش برای بازگردانی وضعیت قبلی در صورت شکست راه‌اندازی.
- 📦 نصب یکپارچه برنامه، LuCI و هسته با یک فایل IPK یا APK؛ به‌روزرسانی از داخل برنامه.

## 💾 نصب و پیش‌نیازها

روتر باید OpenWrt، LuCI، فایروال nftables و پشتیبانی TProxy داشته باشد. معماری بسته باید دقیقا مطابق روتر باشد. قالب APK در این پروژه، بسته مدیر بسته OpenWrt است.

ابتدا معماری، مدیر بسته و فضای آزاد را ببینید:

```sh
ubus call system board
command -v apk || command -v opkg
df -h /overlay /tmp
free -m
```

وابستگی‌ها: `luci-base`، `rpcd`، `ca-bundle`، `ip-full`، `nftables`، `kmod-nft-tproxy`. این موارد وابستگی های سیستمی OpenWrt هستند؛ لازم نیست همه را از قبل جداگانه نصب کنید. مدیر بسته هنگام نصب پل، موارد موجود را نگه می دارد و موارد نصب نشده را از مخزن همان نسخه OpenWrt می گیرد. برای این کار روتر باید به اینترنت و مخزن سازگار دسترسی داشته باشد. فایل پل شامل خود برنامه، پنل مدیریتی آن و هسته Xray است؛ این وابستگی های سیستمی داخل فایل پل قرار ندارند. برای تفکیک ایران، dnsmasq باید از `nftset` پشتیبانی کند؛ اگر نسخه فعلی این قابلیت را ندارد، نصب نسخه سازگار `dnsmasq-full` لازم است. فضای نصب به معماری و نسخه هسته بستگی دارد؛ برای دانلود، استخراج و نگه‌داری نسخه قبلی، فضای موقت هم لازم است.

### RAM و فضای ذخیره‌سازی

| مورد | بودجه پیشنهادی |
|---|---|
| RAM روتر | دست‌کم **۲۵۶ مگابایت**؛ برای فایل‌های کامل مسیریابی و چند اتصال هم‌زمان **۵۱۲ مگابایت یا بیشتر** مناسب‌تر است |
| فضای آزاد پیش از نصب | دست‌کم **۱۵۰ مگابایت**؛ برای فایل‌های کامل و به‌روزرسانی راحت‌تر **۲۵۰ مگابایت یا بیشتر** در نظر بگیرید |
| برنامه، رابط و هسته نصب‌شده | حدود **۷۵ تا ۸۵ مگابایت** با موتورهای خروجی بومی؛ فایل دانلودی فشرده کوچک‌تر است |
| فایل‌های مسیریابی | بسته به منبع؛ نسخه Lite ایران حدود **۲ مگابایت** و فایل‌های کامل مرجع حدود **۲۴ مگابایت** هستند؛ حجم دقیق هر فایل در مسیریابی نمایش داده می‌شود |
| RAM هنگام کار | برای هسته و پایش در حالت سبک حدود **۳۵ مگابایت** مشاهده می‌شود؛ با روش اتصال، فایل‌ها، تعداد دستگاه‌ها و اسکن بیشتر می‌شود. آزادبودن RAM را از وضعیت OpenWrt بررسی کنید |

بودجه‌های بالا برای برنامه‌ریزی نصب‌اند، نه سقف ثابت مصرف. به‌روزرسانی هسته یا فایل‌های مسیریابی موقتا به فایل جدید و نسخه قبلی هم‌زمان نیاز دارد. سایر سرویس‌های روتر هم از RAM و فضای آزاد استفاده می‌کنند. برای فلش کم‌حجم از فضای نصب کافی یا extroot استفاده کنید.


۱. فایل نصب پل مخصوص معماری روتر را از [انتشارهای رسمی پل](https://github.com/dreamboxone/pol/releases) دریافت کنید.
۲. فایل‌های همراه SHA-256 انتشار را بررسی کنید.
۳. بسته‌ها را به روتر، مثلا پوشه `/tmp`، انتقال دهید.
۴. فقط فایل نصب پل مخصوص معماری روتر را در `/tmp` قرار دهید؛ فایل نصب برنامه‌های دیگر یا نسخه‌های قبلی را در این پوشه نگه ندارید. سپس فرمان متناسب با OpenWrt خود را اجرا کنید:

```sh
# OpenWrt با APK
apk add --allow-untrusted /tmp/*.apk

# OpenWrt قدیمی با OPKG
opkg install /tmp/*.ipk
```

در OpenWrt جدید، APK و در نسخه‌های قدیمی‌تر، OPKG را به کار ببرید. وابستگی‌ها از مخزن همان نسخه OpenWrt نصب می‌شوند.

۵. صفحه LuCI را تازه کنید و به **Services → Pol** بروید. در اولین نصب سرویس خاموش است.

> هم‌زمان زیرگذر، Passwall، HomeProxy، Nikki یا هر پراکسی شفاف دیگری را برای همان شبکه روشن نگذارید. پل برای جدول‌های شناخته‌شده جلوی شروع را می‌گیرد؛ این تشخیص شامل همه نرم‌افزارهای احتمالی نیست.

## 🚀 شروع سریع

۱. از بالای صفحه زبان فارسی و تم دلخواه را انتخاب کنید. «همراه تم دستگاه» از تنظیم روشن/تاریک سیستم مرورگر پیروی می‌کند.
۲. یکی از روش‌های زیر را آماده کنید: **کلادفلر ← ساخت Worker**، **تنظیمات ← وارد کردن کانفیگ** یا **تنظیمات ← ساخت اکانت WARP/MASQUE**.
۳. در خانه نوع و روش اتصال را انتخاب کنید. تنظیمات به‌محض تغییر اعمال می‌شوند؛ دکمه Save & Apply وجود ندارد.
۴. اگر عبور کل شبکه را می‌خواهید، در اتصال، «اتصال تمام دستگاه‌های شبکه» روشن و رابط LAN درست، معمولا `br-lan`، باشد.
۵. دکمه اصلی خانه را روشن کنید. «هسته فعال است» یعنی پردازش Xray راه افتاده؛ این وضعیت به‌تنهایی دسترسی اینترنت را تضمین نمی‌کند. مرورگر دستگاه LAN یا اسکن اتصال را برای بررسی مسیر آزمایش کنید.
۶. اگر اتصال برقرار نشد، گزارش را بررسی و تنظیمات یا روش اتصال را عوض کنید.

## ☁️ انواع اتصال

### آماده‌سازی حساب Cloudflare

راهنمای شماره دار و لینک های هر مرحله در برگه **کلادفلر** برنامه قرار دارد. برای روش Worker، یک حساب Cloudflare، شناسه حساب و API Token لازم است. برای نشانی workers.dev نیازی به خرید دامنه ندارید.

۱. وارد [داشبورد Cloudflare](https://dash.cloudflare.com/) شوید و حساب موردنظر را انتخاب کنید.
۲. به **Workers & Pages** بروید و زیر‌دامنه workers.dev حساب را تنظیم کنید. نشانی نهایی از نام Worker و همین زیر‌دامنه ساخته می‌شود. [راهنمای رسمی workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/).
۳. **Account ID** همان حساب را از داشبورد کپی کنید؛ این مقدار ۳۲ کاراکتری با Zone ID دامنه فرق دارد.
۴. در [API Tokens](https://dash.cloudflare.com/profile/api-tokens) Create Token را بزنید و در Token name نامی مانند Pol Worker وارد کنید. در بخش Policies گزینه **Start from scratch (Custom) → Start with an Account policy** را انتخاب کنید و دسترسی را به همین حساب محدود کنید. گزینه‌های Zone policy و User policy برای این روش لازم نیستند. برای ساخت Worker جدید، در مجوزهای قدیمی **Account → Workers Scripts → Edit** و در مدل جدید **Workers Admin** در سطح محصول Workers لازم است. Editor برای ویرایش Worker موجود است. [راهنمای رسمی مجوزها](https://developers.cloudflare.com/workers/authorization/workers/).
۵. توکن را کپی و در جای امن نگه دارید. Token، Account ID و UUID سه مقدار متفاوت هستند.

### ساخت Worker و اتصال در پل

۱. زبانه **کلادفلر** پل را باز کنید و Token و Account ID را در فیلدهای مربوط بگذارید.
۲. نامی جدید مانند `pol-home-123` انتخاب کنید: ۳ تا ۴۱ کاراکتر، شروع با حرف کوچک انگلیسی و شامل حروف کوچک، عدد و خط تیره.
۳. «ساخت Worker» را بزنید و تا پایان عملیات صبر کنید. دامنه و UUID خودکار در تنظیمات اتصال قرار می‌گیرند. توکن در تنظیمات یا گزارش‌ها ذخیره نمی‌شود.
۴. در **تنظیمات پایه**، Worker و روش معمولی را انتخاب کنید. برای شروع، آدرس اتصال را خالی و پورت را ۴۴۳ بگذارید.
۵. در **خانه** دکمه اصلی را روشن کنید و اینترنت را از یک دستگاه متصل به روتر بررسی کنید.
۶. اگر اتصال برقرار نشد، روش فرگمنت یا یک IP تمیز از اسکن را آزمایش کنید. پیش از فرگمنت، فیلد ECH را خالی کنید.

### استفاده از Worker موجود

اگر Worker سازگار دارید، در **خانه ← تنظیمات پایه** دامنه، UUID و مسیر WebSocket آن را وارد کنید؛ یا لینک VLESS آن را در بخش واردکردن کانفیگ قرار دهید. دامنه بدون `https://` و بدون مسیر وارد می‌شود. دامنه Worker به‌تنهایی کافی نیست؛ UUID و تنظیمات همان Worker هم لازم است.

| فیلد | کاربرد |
|---|---|
| دامنه Worker | میزبان WebSocket و دامنه پیش‌فرض TLS؛ بدون `https://` |
| UUID | شناسه اتصال همان Worker؛ محرمانه است |
| آدرس اتصال / IP تمیز | IP یا دامنه‌ای که هسته به آن وصل می‌شود؛ نام Worker در Host حفظ می‌شود |
| پورت | پیش‌فرض ۴۴۳؛ پورت TLS مورد پشتیبانی مقصد را وارد کنید |
| مسیر WebSocket | پیش‌فرض `/?ed=2560` |
| SNI ورکر | اختیاری؛ اگر خالی باشد دامنه Worker استفاده می‌شود؛ گواهی مقصد باید معتبر باشد |

استقرار، نام موجود را جایگزین نمی‌کند. اگر Cloudflare استقرار را انجام دهد ولی ذخیره محلی شکست بخورد، Worker روی حساب باقی می‌ماند؛ از داشبورد Cloudflare مدیریتش کنید. Worker به‌روزشده مسیر DoH به شکل `https://<worker-host>/<uuid>` هم دارد؛ برای استفاده، همین نشانی را در DNS راه‌دور وارد کنید. به‌روزرسانی بسته، Worker قبلا مستقرشده در حساب شما را خودکار عوض نمی‌کند.

### WARP

در تنظیمات «ساخت حساب WARP» را بزنید، نوع WARP را انتخاب کنید و endpoint را به شکل `162.159.192.1:2408` وارد کنید. روش معمولی WireGuard را اجرا می‌کند و روش مبهم‌سازی نویز UDP می‌افزاید. حساب و کلیدها از API سرویس Cloudflare گرفته می‌شوند؛ دسترسی اینترنت مستقیم روتر لازم است.

### MASQUE

حساب MASQUE مستقل از حساب WARP است. بعد از ثبت حساب، انتقال **h2** یا **h3** را انتخاب کنید. h2 روی TCP/TLS است و روش دومش فرگمنت؛ h3 روی UDP/QUIC است و روش دومش مبهم‌سازی UDP. پورت endpoint باید برای روش انتخابی مناسب باشد. SNI پیش‌فرض `engage.cloudflareclient.com` است. بسته‌بودن UDP در شبکه می‌تواند h3 را از کار بیندازد.

### بدون سرور

این حالت برای TCP فرگمنت TLS و برای UDP نویز می‌سازد و به Worker یا حساب نیاز ندارد. **IP عمومی را تغییر نمی‌دهد** و برای همه سایت‌ها و شبکه‌ها جواب نمی‌دهد. آن را جایگزین تونل رمزگذاری‌شده تا یک سرور خارجی در نظر نگیرید.

### Tor و Psiphon

پل موتورهای Tor و سایفون را مدیریت می‌کند. باینری سایفون و Lyrebird داخل بسته هستند؛ Tor و پایگاه GeoIP آن از مخزن OpenWrt نصب می‌شوند. Tor روی پورت محلی 24805 و سایفون روی 24806 اجرا می‌شوند. دریافت خودکار پل‌های Tor، پل سفارشی و انتخاب کشور خروجی در تنظیمات وجود دارد. برای عبور Tor یا سایفون از اتصال فعلی، خروجی نهایی را انتخاب کنید. در حالت Tor، UDP معمولی مسدود می‌شود. آماده‌شدن موتور و دسترسی واقعی اینترنت جداگانه بررسی می‌شوند.

### کانفیگ واردشده و زنجیره

در تنظیمات، یک لینک VLESS، VMess، Trojan، Shadowsocks، WireGuard، SOCKS یا HTTP(S)، یا JSON با آرایه `outbounds` وارد کنید. برای پروتکل‌هایی خارج از این فهرست، از JSON سازگار با هسته نصب‌شده استفاده کنید.

- ورودی‌ها، DNS و مسیریابی JSON واردشده جای تنظیمات روتر را نمی‌گیرند؛ پل آن‌ها را خودش می‌سازد.
- لینک VLESS با WebSocket و TLS به فیلدهای Worker منتقل می‌شود؛ SNI و اثر انگشت لینک نیز حفظ می‌شوند.
- خروجی JSON تنظیمات **خود پل** را هم می‌توانید دوباره وارد کنید.
- در «پروکسی زنجیره‌ای»، لینک پروکسی دوم را بگذارید: مسیر **دستگاه ← اتصال اصلی ← پروکسی دوم ← اینترنت** می‌شود. خالی‌کردن فیلد زنجیره را حذف می‌کند.
- تنظیمات پیشرفته خروجی روی JSON واردشده بازنویسی نمی‌شود؛ باید داخل JSON تنظیمش کنید.

| تاخیر فرگمنت | `1-1` | میلی‌ثانیه؛ در روش فرگمنت استفاده می‌شود |

| DNS برای ECH | خالی / خاموش | IP یا URL از نوع HTTPS DoH؛ فقط Worker معمولی؛ هم‌زمان با فرگمنت پذیرفته نمی‌شود |
| TCP Fast Open | خاموش | برای اتصال Worker؛ نتیجه به پشتیبانی شبکه و هسته بستگی دارد |

تغییر هر مقدار هنگام روشن‌بودن سرویس می‌تواند آن را دوباره راه‌اندازی کند. ابتدا تنظیمات درست را خروجی بگیرید. برای آزمایش ECH ابتدا روش معمولی را انتخاب کنید؛ برای رفتن به فرگمنت ابتدا فیلد ECH را خالی کنید. هیچ روش عبوری تضمین اتصال روی تمام ISPها ندارد.

## 🔎 اسکن واقعی اتصال

در زبانه اتصال و حالت Worker، WARP یا MASQUE، بخش اسکن نمایش داده می‌شود:

۱. حساب یا اطلاعات Worker را کامل کنید و روش اتصال را انتخاب کنید.
۲. حداکثر **۱۲ آدرس یکتا** وارد کنید، هر کدام در یک خط. Worker: IP یا دامنه بدون پورت؛ پورت از فیلد اتصال گرفته می‌شود. WARP/MASQUE: `host:port` یا `[IPv6]:port`.
۳. «اسکن اتصال» را بزنید. پل برای هر مورد هسته موقت با ورودی HTTP محدود به loopback اجرا می‌کند و درخواست HTTPS با گواهی معتبر به `www.gstatic.com/generate_204` می‌فرستد.
۴. نتایج موفق، از تاخیر کمتر مرتب می‌شوند. «استفاده از این آدرس» آدرس انتخابی را ذخیره و در صورت روشن‌بودن سرویس اعمال می‌کند.

اسکن **TCP ping یا صرفا بازبودن پورت نیست**؛ عبور درخواست از مسیر انتخابی را می‌سنجد. زمان نشان‌داده‌شده زمان همان درخواست است و تست سرعت دانلود نیست. اسکن‌ها برای محدودکردن مصرف RAM ترتیبی‌اند، هر مورد حداکثر حدود ۱۲ ثانیه زمان دارد و به تنظیم فعال و فایروال دست نمی‌زنند. اگر زنجیره تنظیم باشد، درخواست از زنجیره هم عبور می‌کند. مسدودبودن مقصد آزمایش، DNS یا خطای حساب می‌تواند همه نتایج را ناموفق کند. نتیجه به شبکه فعلی وابسته است؛ انتخاب آدرس خودکار نیست.

## 🇮🇷 تفکیک ترافیک ایران و فایل‌های مسیریابی

۱. زبانه **مدیریت ترافیک** را باز کنید.
۲. در کارت **GeoIP** منبع فایل آدرس‌های IP و در کارت **GeoSite** منبع فایل دامنه‌ها را انتخاب کنید. منابع Chocolate4U کامل و Lite، نسخه Release، Loyalsoldier، MetaCubeX، CDN و runetfreedom در فهرست هستند. برای فایل ایران، منبعی را انتخاب کنید که گروه `IR` داشته باشد؛ نبود این گروه با پیام خطا اعلام می‌شود و فایل قبلی باقی می‌ماند.
۳. دکمه **به‌روزرسانی فایل** هر کارت را جداگانه بزنید. حجم و تاریخ و ساعت آخرین دریافت زیر همان فایل دیده می‌شود. نشانی HTTPS سفارشی هم قابل ورود است.
۴. پس از دریافت هر دو فایل، DNS مستقیم ایران را مشخص و **تفکیک ترافیک ایران** را روشن کنید.

GeoIP، IPهای ایران را در فایروال **پیش از TProxy و ورود به هسته** مستقیم می‌کند. DNS جداگانه پل، دامنه‌های GeoSite را از DNS مستقیم پاسخ می‌دهد و IP آن‌ها را، حتی با میزبانی خارجی، وارد مجموعه‌های مستقیم nftset می‌کند. DNS خارجی به ورودی DNS هسته فرستاده می‌شود. نام‌های محلی شبکه به DNS خود روتر سپرده می‌شوند.

تفکیک ایران پیش از فهرست دامنه‌های مسدود پل قرار دارد؛ وقتی روشن است، مقصد ایرانی مستقیم عبور می‌کند. برای ثبت IP پاسخ دامنه‌ها، `dnsmasq` باید پشتیبانی nftset داشته باشد؛ در غیر این صورت برنامه پیش از فعال‌سازی پیام می‌دهد و باید نسخه مناسب `dnsmasq-full` را از مخزن همان OpenWrt نصب کنید. تنظیمات DNS سرویس اصلی روتر بازنویسی نمی‌شوند.

در راه‌اندازی مجدد اتصال، نگاشت‌های دامنه تا پایان مهلت خود حفظ می‌شوند. با خاموش‌کردن پل پاک می‌شوند. مرورگر یا اپی که DNS رمزگذاری‌شده مستقل دارد لزوما از DNS پل استفاده نمی‌کند؛ در این حالت قواعد هسته و GeoIP همچنان در تشخیص مقصد نقش دارند.

### آدرس‌های مستقیم و استثناهای DNS Rebind

در برگه «مدیریت ترافیک»، بخش «آدرس‌ها و دامنه‌های مستقیم» برای افزودن و حذف IP، بازه CIDR و دامنه است. ورودی‌هایی مانند `1.2.3.4`، `192.0.2.0/24`، `geoip:ir` و `ext:geoip_IR.dat:ir` پذیرفته می‌شوند؛ فایل ارجاع‌شده باید در پوشه قوانین موجود باشد. دامنه ساده، زیردامنه‌هایش را نیز شامل می‌شود؛ پیشوندهای `domain:`، `full:`، `regexp:` و `geosite:` هم قابل استفاده‌اند. قواعد مستقیم پیش از مسدودسازی اجرا می‌شوند.

در بخش «سایت‌های دارای ضعف امنیتی Rebind Attack» فقط دامنه‌های مورد اعتماد را اضافه کنید که برای کارکرد صحیح به پاسخ DNS خصوصی نیاز دارند. این استثناها در dnsmasq اعمال می‌شوند؛ محافظت دیگر دامنه‌ها و استثناهای قبلی روتر حفظ می‌شوند. حذف یک مورد فقط استثنایی را برمی‌دارد که پل افزوده باشد.

در «فایل‌های مسیریابی»، منبع GeoIP و GeoSite را جداگانه انتخاب و هر فایل را مستقل به‌روزرسانی کنید. حجم و تاریخ دریافت هر فایل نمایش داده می‌شود. مسیر پیش‌فرض `/etc/pol/geo` است؛ برای حافظه جانبی می‌توان مسیری زیر `/mnt/` یا `/opt/` انتخاب کرد. پس از تغییر مسیر، فایل‌ها را در مسیر جدید دریافت کنید. به‌روزرسانی خودکار روزانه یا هفتگی، هنگام روشن بودن پل انجام می‌شود و برای هر فایل جداگانه قابل انتخاب است.

> برای فعال‌کردن تفکیک ترافیک ایران، ابتدا هر دو فایل GeoIP و GeoSite را در برگه مدیریت ترافیک دریافت کنید. فایل‌ها باید معتبر و دارای داده ایران باشند. تا آماده‌شدن هر دو فایل، کلید فعال‌سازی قابل استفاده نیست؛ بک‌اند نیز درخواست فعال‌سازی بدون فایل معتبر را رد می‌کند.

تنظیمات ضروری در کارت «تنظیمات پایه» فقط در صفحه خانه در دسترس‌اند: نوع و روش اتصال، دامنه و UUID ورکر یا endpoint متناسب با نوع اتصال، DNS، رابط LAN و اتصال تمام دستگاه‌های شبکه. فرگمنت، SNI اختصاصی ورکر، پروکسی زنجیره‌ای و سطح گزارش در «تنظیمات پیشرفته» قرار دارند.

## 📊 چهار کارت وضعیت و کلید اصلی

در زبان فارسی، کارت‌ها از راست به چپ به این ترتیب هستند:

- **وضعیت:** نوع اتصال، سرور، پینگ، IP خروجی و کره پرچم کشور خروجی. آدرس‌ها به‌طور پیش‌فرض محو هستند و با اشاره یا فوکوس دیده می‌شوند. تا دریافت کشور واقعی، کره عمومی نمایش داده می‌شود.
- **هسته:** نام و نسخه Xray و وضعیت اجرای پردازش آن. اجرای هسته به‌تنهایی به معنی دسترسی اینترنت نیست.
- **بررسی اتصال:** بررسی جداگانه Telegram، YouTube و Google از داخل اتصال پل. بعد از روشن‌کردن سرویس، دکمه سایت موردنظر را بزنید؛ نتیجه و زمان پاسخ کنار نام آن دیده می‌شود.
- **میزان مصرف:** ارسال، دریافت و مجموع بر حسب GB اعشاری؛ زبانه‌های عمودی برای امروز، ۷ روز اخیر و ۳۰ روز اخیر. ترافیک مستقیم ایران که پیش از هسته عبور می‌کند در این اعداد نیست.

کلید کشویی اصلی زیر این چهار کارت است. خاموش‌کردن آن پردازش‌های هسته، DNS اختصاصی و بررسی اتصال را متوقف و عملیات شبکه در حال اجرا را لغو می‌کند. آمار مصرف با بازکردن دوباره صفحه صفر نمی‌شود؛ هر ۱۵ ثانیه نمونه‌برداری، هر ۵ دقیقه و هنگام توقف ذخیره می‌شود. قطع ناگهانی برق ممکن است آمار بعد از آخرین ذخیره را از بین ببرد. شمارش از زمان نصب نسخه دارای این قابلیت شروع می‌شود.

برای دیدن توضیح هر گزینه، علامت **؟** کنار همان عنوان را بزنید. با کلیک بیرون پنجره، Escape یا جابه‌جایی صفحه راهنما بسته می‌شود.

## 🧭 مسیریابی و DNS

در اتصال، رابط Linux شبکه LAN را تعیین کنید؛ برای بیشتر روترها `br-lan` است، نه نام منطقی UCI مثل `lan`. فقط ترافیک ورودی از همان رابط گرفته می‌شود؛ ترافیک ایجادشده توسط خود روتر خودکار از تونل عبور نمی‌کند.

در مسیریابی، دامنه‌ها را هرکدام در یک خط بنویسید؛ مانند `example.com`. دامنه ساده با زیر‌دامنه‌هایش تطبیق داده می‌شود. پیشوندهای معتبر Xray مثل `full:` و `regexp:` هم به هسته منتقل می‌شوند. اولویت قواعد: **DNS ← تفکیک ایران در صورت فعال‌بودن ← مسدود ← مستقیم ← شبکه خصوصی ← اتصال نهایی**. دامنه‌ای که در هر دو فهرست باشد مسدود می‌شود.

DNS راه‌دور در زبانه اتصال قابل تغییر است. درخواست‌های DNS پورت ۵۳ دستگاه‌های LAN در حالت شفاف به ورودی DNS پل هدایت می‌شوند. DNS خصوصی داخل خود اپلیکیشن‌ها، DoH مرورگر و DoT دستگاه لزوما از این تنظیم پیروی نمی‌کنند. قوانین دامنه و DNS باید با هم در شبکه واقعی آزمایش شوند.

| مورد رزروشده | مقدار |
|---|---|
| SOCKS محلی | `127.0.0.1:24800` |
| HTTP محلی | `127.0.0.1:24801` |
| ورودی‌های شفاف / DNS | پورت‌های ۲۴۸۱۰ تا ۲۴۸۱۳؛ DNS تفکیکی ۲۴۸۱۴ و API داخلی آمار ۲۴۸۱۵ |
| جدول مسیر | `120` |
| علامت nftables | `0x40000000` |

پروکسی محلی فقط روی روتر قابل استفاده است؛ روی WAN یا LAN منتشر نمی‌شود. برای حالت محلی، «اتصال تمام دستگاه‌های شبکه» را خاموش کنید. نمونه بررسی از خود روتر، در صورت نصب curl:

```sh
curl --proxy http://127.0.0.1:24801 https://www.gstatic.com/generate_204 -I
```

## 📋 گزارش و عیب‌یابی

در زبانه گزارش، فیلتر همه/برنامه/هسته، تازه‌سازی، توقف نمایش زنده و دریافت فایل وجود دارد. تازه‌سازی خودکار حدود هر ۵ ثانیه است. توقف نمایش فقط نمایش زنده را متوقف می‌کند؛ سرویس همچنان کار می‌کند. سطح گزارش هسته را در اتصال انتخاب کنید؛ Debug برای بررسی موقت است.

| مشکل | بررسی پیشنهادی |
|---|---|
| منوی پل دیده نمی‌شود | از LuCI خارج و دوباره وارد شوید؛ نصب بسته و فعال‌بودن rpcd را بررسی کنید |
| فونت یا ظاهر قدیمی است | صفحه را با Ctrl+F5 باز کنید یا کش مرورگر را پاک کنید؛ فونت محلی همراه بسته است |
| هسته روشن است ولی اینترنت ندارم | حساب، endpoint، دامنه و UUID، DNS، ساعت روتر و نتیجه اسکن را بررسی کنید |
| مسیریابی شبکه شروع نمی‌شود | پراکسی شفاف دیگر، جدول مسیر ۱۲۰ و نام واقعی رابط LAN را بررسی کنید |
| ثبت حساب یا استقرار شکست می‌خورد | دسترسی مستقیم روتر به Cloudflare، ساعت، Token و مجوز حساب را بررسی کنید |
| MASQUE h3 ناموفق است | امکان بسته‌بودن UDP وجود دارد؛ h2 را با endpoint مناسب آزمایش کنید |
| تغییر مقدار پذیرفته نمی‌شود | پیام خطا را بخوانید؛ بازه‌ها باید صعودی و ECH/فرگمنت ناسازگار خاموش باشند |
| Tor یا Psiphon کار نمی‌کند | وضعیت موتور، پل‌های Tor و دسترسی مسیر اصلی را بررسی کنید |
| به‌روزرسانی پیدا نمی‌شود | دسترسی GitHub، وجود Release و فایل سازگار معماری را بررسی کنید |

فرمان‌های تشخیص روی روتر:

```sh
/usr/libexec/rpcd/pol version
ubus call pol status
logread -e pol-app
logread -e pol-core
nft list table inet pol
ip -4 rule show
ip -6 rule show
```

گزارش‌ها در حلقه محدود `logd` با برچسب‌های `pol-app` و `pol-core` نگه‌داری می‌شوند و پس از راه‌اندازی مجدد باقی نمی‌مانند. پیش از ارسال گزارش، نشانی‌ها و داده‌های خصوصی را بازبینی کنید. برای پشتیبانی از [گروه تلگرام](https://t.me/routekernel1) یا [Issues](https://github.com/dreamboxone/pol/issues) استفاده کنید؛ مدل روتر، نسخه OpenWrt، معماری، نسخه پل و متن خطای بدون کلید و Token را بفرستید.

## 🔄 به‌روزرسانی و پشتیبان‌گیری

در زبانه به‌روزرسانی ابتدا «بررسی نسخه‌ها» را بزنید:

- **هسته:** انتشار رسمی `XTLS/Xray-core`؛ فایل معماری درست و SHA-256 بررسی می‌شود، هسته جدید آزمایش و در صورت شکست راه‌اندازی نسخه قبلی بازگردانده می‌شود.
- **برنامه:** انتشار `dreamboxone/pol`؛ بسته متناسب مدیر بسته و معماری نصب می‌شود. بسته کامل برنامه، LuCI و هسته را نصب می‌کند. پس از نصب، صفحه را دوباره باز کنید و گزارش را بخوانید.
- عملیات طولانی در پس‌زمینه انجام می‌شوند تا محدودیت زمانی rpcd مانع نشود. هنگام عملیات دوباره دکمه را نزنید.

در زبانه **تنظیمات**، از بخش **پشتیبان‌گیری و بازیابی** با دکمه **پشتیبان‌گیری** فایل JSON بگیرید. برای بازگرداندن آن، دکمه **بازیابی** را بزنید و فایل پشتیبان پل را انتخاب کنید. وضعیت روشن/خاموش جاری با واردکردن فایل خودکار تغییر نمی‌کند؛ سایر تنظیمات واردشده هنگام فعال‌بودن سرویس ممکن است اتصال را راه‌اندازی مجدد کنند.

> فایل خروجی شامل UUID، کلید حساب‌ها و اطلاعات پروکسی است. آن را عمومی منتشر نکنید. فایل تنظیمات روتر در `/etc/pol/settings.json` با دسترسی محدود ذخیره می‌شود. Token استقرار Cloudflare در این فایل ذخیره نمی‌شود.

## 🗑️ حذف برنامه

ابتدا از **تنظیمات ← خروجی تنظیمات** پشتیبان بگیرید و روی رایانه ذخیره کنید. سپس در SSH روتر سرویس را متوقف و اجرای خودکار را خاموش کنید:

```sh
/etc/init.d/pol stop
/etc/init.d/pol disable
```

فقط فرمان مربوط به مدیر بسته روتر خودتان را اجرا کنید:

```sh
# OpenWrt با APK
apk del pol

# OpenWrt قدیمی با OPKG
opkg remove pol
```

برنامه، رابط LuCI و هسته همراه با همین یک بسته حذف می‌شوند. تنظیمات، آمار مصرف و فایل‌های مسیریابی داخل `/etc/pol` ممکن است برای نصب دوباره باقی بمانند. اگر دیگر به تنظیمات و کلیدهای ذخیره‌شده نیاز ندارید، برای پاک‌کردن کامل آن‌ها فرمان زیر را اجرا کنید. این مرحله بدون پشتیبان قابل بازگشت نیست:

```sh
rm -rf /etc/pol
```

صفحه LuCI را تازه کنید. اگر منوی پل همچنان دیده می‌شود، از پنل خارج و دوباره وارد شوید.

### حذف Worker از پل و Cloudflare

در برگه **کلادفلر**، کارت **ورکر ذخیره‌شده** دامنه فعلی را نشان می‌دهد. با دکمه **حذف از پل** اطلاعات اتصال آن از روتر پاک می‌شود؛ اگر اتصال Worker روشن است، ابتدا آن را خاموش کنید. این دکمه Worker را از اکانت Cloudflare حذف نمی‌کند.


حذف پل از روتر، Worker حساب Cloudflare را حذف نمی‌کند. برای حذف آن، در داشبورد **Workers & Pages**، Worker موردنظر را باز کنید و از تنظیمات گزینه حذف را انتخاب کنید. ابتدا مطمین شوید دستگاه دیگری از آن استفاده نمی‌کند. توکن را هم در صفحه API Tokens می‌توانید غیرفعال یا حذف کنید.
